# Lines

Desktop futures charting terminal. Rust + GPUI. Market data through provider adapters: CQG WebAPI (protobuf/WSS; mock + untested live), the Coinbase Exchange public feed (JSON/WSS + REST, dev tool), Kraken public spot and perpetuals (JSON/WSS + REST, book checked against Kraken's CRC-32), and replays of imported Sierra Chart data (personal dev tool).

## Docs

- `ROADMAP.md`: milestones and status. Update the status in the change that finishes a milestone.
- `docs/decisions/`: decision records. Accepted ones are binding; supersede, never rewrite.
- `docs/briefs/`: task briefs for upcoming milestones (e.g. the Sierra Chart importer).
- `docs/design.md`: UI design principles and budgets. Binding for every UI change.
- `docs/positioning.md`: who Lines is for, how it differs, what's out of scope, published benchmarks.
- `docs/inspiration.md`: behaviours worth adopting from open-source projects, by area, with licence notes (GPL/LGPL/AGPL: behaviour only, never code).

Catalog products (ids are permanent): `ES` 1, `NQ` 2, `ZN` 3, `MES` 4, `MNQ` 5, `BTC/USD` 1001, `ETH/USD` 1002 (Coinbase), `BTC/USD.KR` 1003, `ETH/USD.KR` 1004 (Kraken spot), `BTC-PERP.KR` 1101, `ETH-PERP.KR` 1102 (Kraken Futures perpetuals). A crypto pair is its exchange's own market, so each exchange's pair is its own product. Contracts are computed, never listed: `ContractKey { product, delivery }`, with `Delivery::Monthly { year (4-digit), month }` for futures and `Delivery::Spot` for spot products and perpetual swaps (one contract that never expires or rolls; no separate perpetual variant is needed). Canonical label: `ESZ26` (2-digit year); `--instrument` takes a product (`ES`, followed to its front month) or a contract (`ESZ26`, `ESZ2026`). Provider symbols are derived by rule: CQG root + month code + last year digit (ES→`EP`, so `EPZ6`; NQ→`ENQ`, ZN→`TYA`; only `EP` verified, via the mock; MES/MNQ unmapped). Coinbase maps `BTC-USD`, `ETH-USD` (spot). Kraken maps spot `BTC/USD` (REST `XBTUSD`), `ETH/USD`, and Futures `PF_XBTUSD`, `PF_ETHUSD`. Sierra maps roots ES, NQ, MES, MNQ (`NQZ5.CME`, `NQH25-CME`, `NQH25_FUT_CME`). The mock resolves `EP` and any `EP` contract symbol.

`recordings/`, `*.lfr`, `*.scid`, `*.depth` are gitignored. Recordings may contain licensed data; committed fixtures must be synthetic (tests build them in code).

## Rules

- The repo is public under FSL-1.1-ALv2 (`LICENSE.md`, decision 0014). Never commit credentials, account IDs, vendor usernames, vendor protos/kits, or anything derived from licensed data, including in screenshots and docs.
- Live vendor connectors (Rithmic, CQG production) belong in a private module (decision 0014). Public code may depend only on the provider/broker traits. They plug in through `lines_feed::extension::SourceExtension`, `lines_trading::extension::BrokerExtension` and `lines_app::run(Extensions)` (decision 0020); no vendor name appears in public code beyond the extension API, and the public binary registers none (`crates/lines-app/tests/extension.rs` runs a dummy source headless, records and replays it; `tests/broker_extension.rs` registers a dummy broker; `lines-trading/tests/extension.rs` drives one through the core).
- Public builds ship only mock, replay, Coinbase and paper (`docs/release.md`). The real CQG connection (`Source::Cqg`, `--source cqg`, `--cqg-url`/`--private-label`/`--client-app-id`, the `LINES_CQG_*` env vars) exists only with the off-by-default `vendor-cqg` feature on `lines-feed`/`lines-app`. The CQG mock, `CqgSession` and `cqg-proto` stay public (mock and CQG-format replays need them). Never add `vendor-cqg` to default features or release builds.
- Never drive the real mouse or keyboard or capture the screen. Verify UI with screenshot mode and unit tests; the owner checks live behaviour.
- `cargo` may not be on PATH: use `~/.cargo/bin/cargo.exe`.

## Invariants (enforced by tests)

- Prices are vendor-neutral: `Price(i64)` is an integer count of the *catalog product's* price unit, whose size is an exact rational `PriceScale` defined once in `catalog.rs` (ES/NQ/MES/MNQ: 1/100, tick 25 units). Quantities are `Qty(i64)`, a count of `10^-decimals` of the base unit (futures: decimals 0). No core type is in any vendor's units.
- Each provider converts its wire values exactly at its edge. CQG converts `scaled_price` with `UnitConverter`, from `correct_price_scale` turned into an exact rational. Coinbase parses decimal text, and REST numbers via `RawValue`. Sierra converts `f32 / multiplier` with an f32-relative tolerance, and the result must be on the tick grid. Values that aren't exactly representable are counted (`MarketEvent::Rejected`, import report), never rounded. CQG metadata whose tick disagrees with the catalog is a fatal `BadMetadata`.
- Vendor symbols exist only inside `lines-feed` (the crate-private `catalog::roots` table and `src/{cqg,coinbase,kraken}`) and the dev-only `lines-sierra`. The UI sees `Product`, `ContractKey`, `Capabilities` and the provider id. Bid/ask display is capability-gated.
- `ProviderSession`s do no I/O. HTTP responses arrive as `FrameKind::Http` frames carrying `URL
body` (pre-URL recordings: body only), so recordings contain them and sessions interpret a response by its URL, not their own request plan. Replay drives the same session code; its clock is the recorded frame time (the first recorded frame before any delivery).
- `.lfr` is format **v3**: header = provider, protocol, catalog product symbol, contract key. v2 files still read, with the contract unknown (shown as "contract unknown"; asking a v2 file for a specific contract is an error). v1 is rejected. Replay refuses unknown providers or protocols and product/contract mismatches. A recording holds exactly one contract: if the front month rolls mid-recording, recording stops. Imported data uses provider `lines` / protocol `lines-events-1`. Each frame is one atomic batch, depth included, so the store applies it under one lock and checks for a crossed book only at frame boundaries.
- Sierra import is deterministic (same inputs → byte-identical file). Trades are checked against the book at emit time, never against look-ahead state. Sweep fills (Sierra unbundled trades) are not expected at the touch.
- Products vs contracts (decision 0013): the store is keyed by contract (`ChartData::contract`). `MarketEvent::ContractChanged(key)` retires the old contract's bars (kept, unadjusted, for continuous charts), never mixes them. Front month = `roll::resolve_front`: volume crossover when prior-session volumes are given, else the product's calendar rule, never backwards, never an expired contract. Live feeds following a product re-resolve on every (re)connect. Nothing rolls positions.
- Trading sessions (decision 0017, `lines_core::sessions`): a session belongs to its trade date; the ETH session of trade date D opens at `eth_open` on the calendar day before D (CME's Sunday 17:00 CT open is Monday's session) and closes on D. Hours are exchange-local in an IANA zone (jiff, bundled tzdb, so results never depend on the machine). Holidays/early closes are versioned data (`lines-feed/data/exchange-holidays.txt`, format 1, every date `verified` or `unverified` with sources); a `halt` holiday is not a trade date and its morning belongs to the next trade date's session (`Session::halt`), at most one per gap. Outside a table's coverage weekdays are assumed regular and sessions report `HolidayData::NotCovered`. Session queries never allocate (`lines-core/tests/sessions_no_alloc.rs`).
- Continuous series are display-only (`continuous::build`): unadjusted by default, difference back-adjust as an option (exact, on the tick grid), no ratio adjustment.

- History + live stitch (`lines_core::stitch`, roadmap 4): a history snapshot is bars plus a *closed* `as_of` (includes every trade with `time <= as_of`, none after; CQG's `up_to_utc_time` definition). Live trades with `time <= as_of` are dropped as already counted; later ones are added; trades applied before a late snapshot overwrote their bar are re-applied from a bounded journal (500k trades while history is outstanding, then the newest 3 bars). Open/close follow trade time, not arrival order. Providers must supply a closed `as_of`: CQG `up_to_utc_time` (the mock never stamps a trade at or before its last snapshot); Coinbase candles closed at the bucket end, the forming bar rebuilt from REST trades de-duplicated against websocket trades by `trade_id`. REST lags the websocket by seconds, so id holes (REST newest .. `last_match`, and matches dropped mid-stream) are fetched by id (`trades?after=hi+1`), retried on the keepalive tick, and reported as a history gap after 6 attempts; history is `Complete` only once the REST-to-websocket hole is closed. Every (re)connect requests history from the newest stored bar; the window is `FeedConfig::history_ms` (default 3 days). `ChartData::history` (`Loading`/`Complete`/`Incomplete`/`Unsupported`) is shown as header text.

- Depth (roadmap 5): `MarketEvent::BookClear`/`BookLevel` (new total per price, 0 removes); one frame is one atomic batch. CQG subscribes at `LEVEL_TRADES_BBA_DOM` and maps `TYPE_BID`/`TYPE_ASK` quotes; a snapshot clears the book. The CQG mock keeps a 10-level, one-tick-wide book that shifts with its price walk and is never crossed at a frame boundary. Coinbase uses the public `level2_batch` channel (`level2` needs authentication). Kraken spot subscribes `book` at depth 100; the session keeps its own book truncated to that depth (Kraken expects clients to drop levels pushed past it) and checks Kraken's CRC-32 of the top 10 levels after *every* message (each field is the value in grid units, so the checksum string is integer digits, never a float). A mismatch is counted, clears the book at once (`BookClear`; a book known to be wrong is never shown), and resubscribes; updates are ignored until the fresh snapshot. Kraken Futures books have no checksum: their sequence number must advance by one, and a skip is the same clear-and-resync (counted as a resync, not a `Gap`: `Gap` means dropped trades to the store and the local data store). `FeedStats::{book_checksums_ok, book_checksum_mismatches, book_resyncs}` count all of it. Kraken sessions validate tick and lot size against Kraken's public metadata (`AssetPairs`, Futures `instruments`) before subscribing: a mismatch is a fatal `BadMetadata`. Kraken Futures candle *volumes* are float sums printed to 16 digits (`0.3359999999999999`); only they are snapped, and only within 1e-6 of a grid step (`kraken::num::units_from_float_text`); everything else Kraken sends is parsed exactly from its text. Trades carry `aggressor: Option<Aggressor>`: CQG `sales_condition` (HIT/SELL_SIDE → sell, TAKE/BUY_SIDE → buy), Coinbase from the maker side (opposite), Sierra from the import.

- Local store (`lines-feed/src/disk`, decision 0019): per contract `store-v1/<source>/<contract>/<trade date>.lseg`, append-only **segment v1** (header like `.lfr` v3 + source, encoding, trade date; blocks `u32 len | u32 crc32 | i64 time_us | lines-events-1`, one block per feed frame). Claimed only after `HistoryComplete`: bars from the requested history start, trades from the newest snapshot `as_of` + 1 ms, both to the newest of feed time and trade time. A `Gap` closes the claim; a `HistoryGap` is excluded; a disconnect ends it. Trade claims count only where the segment file still exists (eviction) and stop at the last valid block after a torn-tail cut. Coinbase reports history beyond its page budget as a `HistoryGap`.

- Trading core (`lines-trading`, roadmap 6; decisions 0004/0005/0006/0012/0018): every order action is a `Command` in an `Envelope` (id, `Source`, the input event's `Instant`) through `TradingHandle::submit`; each gets exactly one `Event::Command` result (`Ok(order ids)` or a `Reject` with a `RejectCode` and message). Everything else comes out as `Event`s on `TradingHandle::subscribe` (Order, Fill, Position, Account, Breach, Rebuilt), in order. `TradingCore` is pure (time passed in, no I/O) and runs on the `TradingService` thread; it shares no lock with the UI. Order states move only along `OrderState::can_become` (Submitted → Acked → Working → PartiallyFilled → Filled / Cancelled / Rejected with a reason); nothing is Working before its ack. Money is exact: `Money(i128)` in 1e-10 currency units, `ContractSpec::money_per_unit` must divide exactly; positions are FIFO lots, so realised P&L is exact. Risk (`RiskLimits`: max order qty, max position counting open orders, price band in ticks from the last trade else the mid, daily loss) and prop rules run before the broker; `CancelOrder`, `CancelAll` and `Flatten` never pass through them. Prop rules are data (`RulePreset`, labelled "user-editable approximation", no firm names): trailing drawdown intraday (equity high-water) or end-of-day (closing balances), optional lock at start + X, daily loss per trade date, micro-equivalent contract cap (`Product::micro_equivalent`), profit target, consistency; a breach blocks new orders and, with `liquidate_on_breach`, flattens (`Source::Rule`). Day boundaries are session trade dates (`disk::partition::trade_date`) of the account's `day_product`. Reconnect/restart: `rebuild` replaces balances, positions and open orders from `Broker::snapshot`; orders the broker doesn't know become Cancelled. Every request reaches the broker through `Broker::request_in_context` with a `RequestContext`: `source`, `origin` (`Origin::of`: `Rule`/`Api` automated, the rest manual) and the issuing `PaneContext` (pane contract, `ContractSelection` follows-product or pinned, the resolver's `front_month`), set by `submit_from_pane` (`TradingHandle`/`TradingCore`); plain `submit` sends `pane: None`. The default implementation calls `request`, so brokers that don't need it (paper) ignore it. Latency: click → `Broker::request` is logged as `tracing` target `lines::latency` (`click_to_sent_us`) and kept in a 4096-sample ring (`TradingHandle::latency`).
- Guardrails (`lines-trading/src/guardrails.rs`, roadmap 8b, decision 0006): per account, all optional: max trades per trade date (a round trip flat → position → flat; partial fills don't count, a reversal closes one and opens the next), a losing streak (trade P&L net of every fee; below zero is a loss) → cooldown of N minutes, max daily loss in money (realised + unrealised, separate from prop rules), max position (worst case with open orders), no entries in the last N minutes before the session close. A breach is a lockout (`Cooldown` until a time, `Locked` until the trade date ends) with a reason; denials are `RejectCode::Guardrail` with a short US-English message ("Cooldown: 3 losses in a row, 12 min left"). Exits are never blocked: Flatten, Cancel All, cancels and orders no larger than what is left to close; a modify that adds quantity is checked as an entry. `Command::SetGuardrails`: tighter fields apply at once, looser ones with the next trade date; nothing clears a lockout early. Trade dates from `disk::partition::trade_date` of the account's `day_product`; a fill counts toward the trade date of its own timestamp (the broker's fill time), not the time the core processes it. `Event::Guardrail { account, state, reason, until }` on every change, its end included (the core wakes for it). Saved per account in the trading file (`SavedAccount.guardrails`, format v2). Defaults: `settings.json` `guardrails` keyed by account name (or id), asked for at every start; no editor yet (decision 0021). Screenshot scripts: `guard trades N | streak L/M | loss X | position N | close M`.
- Paper broker (`paper.rs`): deterministic, I/O-free, driven by `market` (feed batches via `lines_feed::listen` and `FeedBridge`) and `poll(now)`. Acks after `latency_ms` (default 25). Rejects off-tick prices, non-positive qty and orders while the product's session is closed. Fill models for resting limits: trade-through (default: a trade strictly through the limit), touch (a trade at the limit), queue estimate (behind the book's size at the price; trades at the price and a shrinking level reduce the queue). Several orders never fill more than a trade printed. Market orders and marketable limits walk the book; liquidity taken isn't reused until that level updates; no book → last trade; neither → reject. Stops trigger on trades at or through the trigger. Fees per quantity unit per side, by product. Brackets and OCO are held broker-side (exits Acked until the entry fills, sized to the fill; an exit fill cancels or shrinks the sibling) and saved in the broker state, so they survive restarts.
- Trading file (`persist.rs`): versioned JSON (`TradingFile`, v2), migrated forward on load (v0 = no `version`; v1 → v2 only moves the version, so a build from before guardrails refuses a file that may hold a lockout instead of dropping it; v1 and v2 are pinned in `persist::tests`), a newer version is refused, writes are atomic (temp + rename); the service saves at most once a second when changed. Orders sent without a broker answer are saved (`in_flight`) and restored `Unresolved`.
- OMS checklist (docs/inspiration.md, one test each in `tests/trading.rs`, `checklist_*`): a command `Reject` is always a **denial** (the core refused, nothing sent); a broker's refusal is `OrderState::Rejected` on a sent order, and the UI labels them DENIED / REJECTED. Cancel All covers submitted and acked orders. A fill during a pending cancel applies (Filled, or Cancelled with its filled quantity); a fill reported after an order finished applies without reopening it. Every fill carries the broker's stable `trade_id` and the core drops repeats (any path); reconciliation (`rebuild`) reports fills the broker made while we weren't listening as one `reconciled` fill with id `recon-<order>-<filled>`, so repeating it never double-counts. Overfill: `OverfillPolicy::Record` (default: the broker's quantity is the truth; `Order::overfill`) or `Reject`, both reported as `Event::Overfill`, never clamped. Accounts have a `TradingState` (Active / ReducingOnly / Halted); prop breaches set it from the preset's `on_breach` (default: daily loss → reducing only until the next trade date, drawdown → halted); reducing only admits orders that close at most the open position less what open orders already close, and marks them `reduce_only`; the paper broker shrinks reduce-only orders as the position shrinks and cancels them when it is flat. Risk adds `max_notional`, `max_submits_per_sec` and `max_modifies_per_sec` (separate windows); cancels and Flatten are never rate limited. Brackets are one-updates-other: an exit's remaining is the bracket's open quantity (entry fills grow both exits, an exit fill shrinks its sibling); with nothing open the sibling is held while the entry still works and cancelled once it is done. `Unresolved` = sent with no known outcome (after a restart or a reconnect whose snapshot lacks it): never drawn as working; the DOM header lists them.
- App trading (roadmap 7; `trading.rs`, `trade_bar.rs`, `dom_trade.rs`, `dom_orders.rs`): the `Trading` global holds a `TradingHandle`; UI actions only `submit` (a channel send stamped with the input event's `Instant`) and never wait. A pump thread applies core events to `TradeState` (its own mutex, never the core's) and bumps a per-account atomic revision; panes poll it with their store revision (`Pane::changed`) and `try_lock` in paint. Paper fills see the pane's own feed (`follow_store`, once per feed). Paper state: `<config dir>/paper/<source>.json` per data source; replays (market clock), screenshots and the bench keep it in memory; a damaged file is moved aside and reported. Accounts: paper only; the pane header names the account with a PAPER badge (word, inverted chip). DOMs start **disarmed**; arming is explicit (header or Ctrl+Shift+Space), never saved, dropped on contract change or when trading becomes impossible, and on focus loss / window deactivation / account change (`ArmPrefs`, on by default). Armed click: bid column buys, ask column sells, limit at the row's **displayed price** (`row × grouping × tick`, the row's lowest; same for grouped rows), Shift = stop market (refused if it would trigger at once); brackets attach only to orders that open or add. Drag (orders column) = modify with a ghost until the order reports the new price; right-click = cancel; neither needs arming. Flatten / Cancel All (header, Ctrl+Shift+F / Ctrl+Shift+A, palette) act on the pane's contract, are always visible and never gated by arming, risk or rules. Order marks: pending outline, held (bracket exit before entry fill) dashed, working solid, partial proportional fill + `filled/qty`; bracket exits by role (`dom_trade::MarkRole`): target `T` in `order_target` notched along its top edge, stop `S` in `order_stop` notched along its bottom edge, entries plain in the side's colour; refusals show as a short tag in the orders column of their row (`dom_trade::short_reason`, e.g. `closed`; `DENIED: closed` when the column is wide enough; clipped to the cell, never over the price) and as one header line with the full message and `×N`, never as dialogs. The mock source's paper broker doesn't check exchange sessions (`TradingSetup::check_sessions`, over a saved file's setting too): it is synthetic and never closes; real sources and replays keep the check. Every trading action is a `commands::TradeCmd` with a key (always Ctrl+Shift or Ctrl+Alt) and a palette entry. Latency budgets live in `#[ignore]`d perf tests only; unit tests check that samples are recorded.
- Pane headers keep a right-hand gutter (`pane::controls_gutter`, sized for `pane::control_labels` and tested) where the hover controls draw, in main windows and pane windows; header content sits in `pane::header_content`, clipped before it, so hover chrome never covers anything (the chart's account chip sits with the contract on the left).
- Tests never assert on what a real-time feed did within a fixed wall-clock time (other builds load the CPU): they run until the condition holds with a generous deadline (`tests/feed.rs` `run_until`), assert on what was delivered, or test the decision with the clock injected (`ChartStore::stale_after_quiet`). Throughput and latency budgets live only in `#[ignore]`d perf tests.
- The UI never blocks on the feed. Sessions decode outside the lock, the store applies events under a short lock, the UI polls an atomic revision every 8 ms and `try_lock`s in paint.
- Transport `recv` must be cancel-safe.
- macOS always builds `gpui_platform` with `font-kit` (target-specific dependency in `lines-app`); without it GPUI's no-op text system renders no text. `lines-app/tests/text_system.rs` (no harness, main thread) asserts the platform text system lists fonts and shapes glyphs.
- Screenshot mode exits from inside the app with its own code (quitting the app exits 0 on macOS); every failure exits non-zero with no file.
- Screenshot mode: repeated runs with the same inputs on one machine produced byte-identical PNGs. Output dimensions are checked against `size × scale`.
- Colours are tokens in `crates/lines-app/src/theme.rs` only (a test rejects colour literals in views). Themes derive from the brand palette (ink `#11141B`, violet `#8C7BFF`, paper `#ECEAF4`); violet is the accent and last-price tag, never up/down. Every text token meets WCAG AA (4.5:1) on its backgrounds in all four theme/palette combinations (`theme::tests`). Direction is shown by shape too: one direction's bodies are hollow (bodies under 3 device px each way stay filled).

## Known gaps

- Real CQG connection never exercised. Not implemented: session restore, variable tick tables, quote corrections (counted only), time zones in the UI (axis is UTC), tick-arrival→frame latency measurement (decision 0001). Decision 0013 gaps: no live source of prior-session volume yet, so feeds use the calendar rule; expiry/roll calendars ignore exchange holidays (provider expiry dates win; session calendars do model them); continuous series are not shown in the UI yet; the Rithmic symbol rule belongs to the private connector (decision 0014).
- Screenshot DPI cannot be overridden on Windows (GPUI reads monitor DPI); `--scale` asserts it instead. Screenshots use the OS UI font, so they differ across machines.
- Store: segments have no resync marker, so a corrupt block mid-file cuts the rest of that day (logged with the byte count). Provider history isn't in segments, so replaying a stored contract rebuilds bars only where trades were stored. The UI doesn't show store usage yet (defaults are in `--help`).
- Indicators: VWAP over history uses bar typical prices (approximate) even where the local store holds those trades; replaying stored trades into the engine at startup would make it exact. The WIT plugin world is designed (doc on `lines_indicators::Indicator`), not built (roadmap 10b).
- Volume profile: from counted trades only (live or replayed), not history bars (no per-price volume in them), so after a connect it is partial (labelled) until a session starts. Readability at DPI 2.0 is by construction (device-pixel snapping) but was not checked here (this machine is DPI 1.0). `ProfileConfig` is saved per chart pane in the workspace file. Off by default.
- External levels: no settings window yet (decision 0021): sources get schema defaults or values set with `levels::runtime::set_settings`. Official builds register sources with `lines_app::Extensions::with_level_source` (decision 0020; `run` forwards them to `levels::register`). A levels replay only matches a market replay recorded in the same session (batches are stamped with the live wall clock). No hotkeys for level toggles (pane menu and palette only).
- DOM/T&S: volume at price counts since data start (trading sessions are not modelled), from live trades only (not history bars).
- Workspaces: tab and pane-header drag-out, pane windows, window placement across monitors and DPI changes were built against GPUI's Windows backend and need the owner's live check (never driven here); macOS/Linux untested. "Dock beside chart" goes beside the chart that last had focus. The closed-tab stack is not saved across restarts. A tab dropped on another window is appended (no drop position). Drop targets use each window's outer bounds. `--bench` measures CPU frame build (`Window::draw`), not GPU or presentation, and isn't in CI yet. The workspace autosaves every 2 s when changed and on close/quit; a crash loses at most those 2 s.
- Kraken: spot OHLC returns only the newest 720 candles (12 hours at 1 minute) whatever `since` asks, so a longer window is reported as a history gap (header shows history incomplete). Spot WebSocket trade-id skips are counted as gaps, not re-fetched. Futures REST trades come 100 per page (at most 30 pages back to the forming bar's boundary, else a gap); the Futures book has no checksum, only sequence numbers. Futures continuity between REST and WebSocket trades is checked by time (Futures trade ids carry no order).
- Coinbase: if the local clock is ahead of Coinbase's, the connect-time bar boundary can be early and trades just before it are dropped as "covered". REST trades are paged back at most 10 × 1000 trades; beyond that the hole is reported as a history gap.
- Sierra: format docs are withdrawn. The sub-trade markers in `open` (`0xfd709ef9` opens an unbundled trade, `0xfd709f01` closes it; swapped before 2026-11-06, which took standalone trades for sweep fills) and the ×100 price multiplier were determined from NQ files only; ES/MES/MNQ are assumed the same. Depth is stamped in whole milliseconds and trades get +1 µs each within a millisecond, so the order of trades and depth inside one millisecond is not in the files. First fills inside the rebuilt book on 2025-09-11: NQZ5 94.9% (6358/6698), NQU5 97.8%; all but 0.1–0.2% of the rest are inside at some batch boundary of their millisecond. The rebuild matches Sierra's own ~10-minute book snapshots. NQZ5 was the deferred contract that day (8k lots traded vs NQU5's 429k), so its thin book (1–2 lots, gaps between levels) is real: use NQU5 for that date. Sierra records at most 100 levels per side. Diagnostics: `cargo run --release -p lines-sierra --example depth_book -- <Data dir> <SYMBOL> <date> [HH:MM:SS ...]`. Recordings imported before format v3 have no contract (read as unknown); re-import to get it.
- Trading (roadmap 6 part 1): headless only (no UI wiring yet), paper broker only. The trading file's location is chosen by the caller (no default path yet). Paper fills ignore exchange matching priority beyond the queue estimate; a triggered stop-limit that isn't marketable rests as a limit with no queue ahead (optimistic under the queue model). Prop presets are generic approximations, not any firm's rules. Rule state is tracked per account in the core; account groups exist in the model but have no group commands yet.
- DOM trading: paper only; click and drag were verified with unit tests and screenshots, not with a live pointer (owner checks). Click→order-sent is measured from the GPUI input handler, not the OS input event. Release p50 ~30 µs; p99 usually < 0.5 ms but OS scheduling of the idle trading thread can push it past 1 ms under load. Account selection per pane only (no account groups in the UI, no account creation UI: defaults are `Paper` and `Paper 50K eval`). Settings for arming and bracket presets wait for the Settings window (6c).
- Symbol picker: searches the built-in catalog only (no provider symbol lookup yet); front months use the calendar rule (no live volume before connecting). The CQG mock serves ES only. Recents/favourites live in `<config dir>/settings.json` (versioned; see Saved files).
- Verified on Windows 11, and by hand on macOS 27 (Apple silicon, Retina 2×; screenshots byte-identical across runs there too). Linux: CI only.
