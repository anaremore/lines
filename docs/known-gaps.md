# Known gaps

<!-- Moved from CLAUDE.md (agent workflow, 2026-11-06). Agents: read the sections for every crate you touch. -->

- Real CQG connection never exercised. Not implemented: session restore, variable tick tables, quote corrections (counted only), time zones in the UI (axis is UTC), tick-arrival→presentation latency (the latency HUD measures receive → the start of a chart's paint, decision 0001). Decision 0013 gaps: no live source of prior-session volume yet, so feeds use the calendar rule; expiry/roll calendars ignore exchange holidays (provider expiry dates win; session calendars do model them); continuous series are not shown in the UI yet; the Rithmic symbol rule belongs to the private connector (decision 0014).
- Screenshot DPI cannot be overridden on Windows (GPUI reads monitor DPI); `--scale` asserts it instead. Screenshots use the OS UI font, so they differ across machines.
- Store: segments have no resync marker, so a corrupt block mid-file cuts the rest of that day (logged with the byte count). Provider history isn't in segments, so replaying a stored contract rebuilds bars only where trades were stored. The UI doesn't show store usage yet (defaults are in `--help`).
- Indicators: VWAP over history uses bar typical prices (approximate) even where the local store holds those trades; replaying stored trades into the engine at startup would make it exact. The WIT plugin world is designed (doc on `lines_indicators::Indicator`), not built (roadmap 10b).
- Volume profile: from counted trades only (live or replayed), not history bars (no per-price volume in them), so after a connect it is partial (labelled) until a session starts. Readability at DPI 2.0 is by construction (device-pixel snapping) but was not checked here (this machine is DPI 1.0). `ProfileConfig` is saved per chart pane in the workspace file. Off by default.
- External levels: no settings window yet (decision 0021): sources get schema defaults or values set with `levels::runtime::set_settings`. Official builds register sources with `lines_app::Extensions::with_level_source` (decision 0020; `run` forwards them to `levels::register`). A levels replay only matches a market replay recorded in the same session (batches are stamped with the live wall clock). No hotkeys for level toggles (pane menu and palette only).
- Footprint and cumulative delta (roadmap 10e): from counted trades only (live or replayed), so history-only bars are candles and delta over history is a bar-level tick-rule estimate (flagged approximate). One cumulative delta per chart (one sub-pane). Trades without an aggressor side are flagged in the footprint (`?N` cells, a legend count) but cumulative delta still ignores them without a flag. The sub-pane divider has no resize cursor on hover (the drag works); hover, drag and wheel in the sub-pane await the owner's live check. A workspace, template or `chart_defaults` holding a cumulative delta (indicator kind `cum_delta`) can't be read by a build from before it (that file is set aside as unreadable and defaults load: the optional-field rule covers new fields, not new kinds). Footprint and cumulative delta are set in the studies menu only (Ctrl+I, the palette's and pane menu's "Studies…"; screenshots: `--study-set`), with no direct keys.
- Pane headers narrower than their tested minimum (chart 700 px) clip the left group at the hover controls' gutter: the account chip loses its ▾ and the PAPER badge can be cut off, so paper vs live is not visible in the header there. Header dropdowns open from the chip's visible part.
- Latency HUD (roadmap 6b): shown in chart headers only (DOM and T&S record nothing and show nothing; receive → paint is per chart). It shares the header's right-hand text: a chart under 1200 px shows p99s only, and a very narrow one still truncates it from the end (the clock warning is a badge on the left and stays). Feed latency needs the trade's exchange time: sources whose trades are stamped at receipt (the mock) read `n/a`. The clock bound includes the link's transit, so a slow link reads as a clock ahead; it is shown for live wall-clock feeds only (never for replays) and has not been seen against a live Coinbase/Kraken feed here (awaiting the owner's check). Order latency comes from the paper broker (its ack is simulated, labeled `ack (sim)`); for real brokers `at − created` mixes the broker's clock with the core's, and a broker that acks bracket exits only when the entry fills, or replays acks after a rebuild, would need its own rule. After the wall clock steps back (NTP), a live feed records nothing until the clock passes the newest recorded second again. Paint latency is measured to the start of this chart's paint, not to the GPU's presentation.
- DOM/T&S: volume at price counts since data start (trading sessions are not modelled), from live trades only (not history bars).
- Workspaces: tab and pane-header drag-out, pane windows, window placement across monitors and DPI changes were built against GPUI's Windows backend and need the owner's live check (never driven here); macOS/Linux untested. "Dock beside chart" goes beside the chart that last had focus. The closed-tab stack is not saved across restarts. A tab dropped on another window is appended (no drop position). Drop targets use each window's outer bounds. `--bench` measures CPU frame build (`Window::draw`), not GPU or presentation, and isn't in CI yet. The workspace autosaves every 2 s when changed and on close/quit; a crash loses at most those 2 s.
- Kraken: spot OHLC returns only the newest 720 candles (12 hours at 1 minute) whatever `since` asks, so a longer window is reported as a history gap (header shows history incomplete). Spot WebSocket trade-id skips are counted as gaps, not re-fetched. Futures REST trades come 100 per page (at most 30 pages back to the forming bar's boundary, else a gap); the Futures book has no checksum, only sequence numbers. Futures continuity between REST and WebSocket trades is checked by time (Futures trade ids carry no order).
- Coinbase: if the local clock is ahead of Coinbase's, the connect-time bar boundary can be early and trades just before it are dropped as "covered". REST trades are paged back at most 10 × 1000 trades; beyond that the hole is reported as a history gap.
- Sierra: format docs are withdrawn. The sub-trade markers in `open` (`0xfd709ef9` opens an unbundled trade, `0xfd709f01` closes it; swapped before 2026-11-06, which took standalone trades for sweep fills) and the ×100 price multiplier were determined from NQ files only; ES/MES/MNQ are assumed the same. Depth is stamped in whole milliseconds and trades get +1 µs each within a millisecond, so the order of trades and depth inside one millisecond is not in the files. First fills inside the rebuilt book on 2025-09-11: NQZ5 94.9% (6358/6698), NQU5 97.8%; all but 0.1–0.2% of the rest are inside at some batch boundary of their millisecond. The rebuild matches Sierra's own ~10-minute book snapshots. NQZ5 was the deferred contract that day (8k lots traded vs NQU5's 429k), so its thin book (1–2 lots, gaps between levels) is real: use NQU5 for that date. Sierra records at most 100 levels per side. Diagnostics: `cargo run --release -p lines-sierra --example depth_book -- <Data dir> <SYMBOL> <date> [HH:MM:SS ...]`. Recordings imported before format v3 have no contract (read as unknown); re-import to get it.
- Journal (roadmap 8c phase 1): no entry/exit chart screenshots yet (`Trade::screenshots` is reserved for phase 2), no P&L views by account or setup, no consistency-rule progress. Open trades aren't saved: a position held across a restart becomes an `incomplete` trade dated from its first fill after the restart, its entry from the core's average price. Hour-of-day stats use the exchange's local hour; the table's times are UTC like the rest of the app. Editing tags and notes inline (typing, Tab, Enter, Esc) is tested as pure logic and shown in screenshots, but awaits the owner's live check. MAE/MFE take a whole market batch after the core: a trade that closes inside a batch also counts that batch's later prices (one batch at most). A live broker's reconciled exit fill arriving before the position report after a restart starts a trade instead of closing a seeded one (paper never reconciles fills at startup).
- Trading (roadmap 6 part 1): headless only (no UI wiring yet), paper broker only. The trading file's location is chosen by the caller (no default path yet). Paper fills ignore exchange matching priority beyond the queue estimate; a triggered stop-limit that isn't marketable rests as a limit with no queue ahead (optimistic under the queue model). Prop presets are generic approximations, not any firm's rules. Rule state is tracked per account in the core; account groups exist in the model but have no group commands yet.
- DOM trading: paper only; click and drag were verified with unit tests and screenshots, not with a live pointer (owner checks). Click→order-sent is measured from the GPUI input handler, not the OS input event. Release p50 ~30 µs; p99 usually < 0.5 ms but OS scheduling of the idle trading thread can push it past 1 ms under load. Account selection per pane only (no account groups in the UI, no account creation UI: defaults are `Paper` and `Paper 50K eval`). The trading switch's opt-in auto-disable settings (`ArmPrefs`) have no editor yet: `settings.json` only, until the Settings window (6c); bracket presets are edited inline in the DOM's panel. The panel's tooltips, the inline preset editor's typing and the narrow panel's ▸ limits overlay were checked with unit tests and screenshots, not a live pointer (owner checks).
- A DOM too narrow for its book even with every column at its minimum (e.g. 8-decimal crypto sizes under about 320 px) leaves out the working-orders column for that frame, so the book stays whole; drag-to-modify and right-click cancel need a wider pane then (the panel still counts working orders, and Cancel all reaches them).
- BE doesn't count unresolved exit orders (the cache keeps them apart from open ones). Harmless on paper (an unresolved paper order was never placed); a live broker whose unresolved exit later fills could let BE leave a stop that flips the position. BE also refuses for the acknowledgment delay right after a new bracket is sent (its exits count while pending); pressing it again works.
- Drawings: no color picker or note editing yet (the Settings window will add colors); a note's text is set when it is placed. Popped-out pane windows don't run drawing commands from keys (clicks and the chart's own keys work; the palette in the main window works). Horizontal lines and rays have no price tag on the axis yet (their level is read against the gridlines). Price auto-scale ignores drawings, so a level outside the bars' range is off screen until scrolled to. Placing, dragging and the pointer cursor were verified with unit tests and screenshots only, not a live pointer (owner checks).
- Strategies (decision 0025, proposed; phase (a)): the core's gate and headless backtests only. There is no in-app host, strategy panel, Stop all button or chart markers yet, so strategies can't run in the app. Level maps carry no named values yet (indicators such as a source's stats). Backtests read levels only from recordings (`--replay-levels`); a synthetic source with no recording is missing. One instance per account and contract; nothing coordinates exposure across instances. A backtest arms its instance once and never re-arms it, as live: over several days, one pause (daily loss, a levels gap) ends trading for the rest of the run (the report's `states` say why). Backtest timers step through market gaps one period at a time (correct, slow over weekends and long stored contracts). Commands the core issues itself (a pause's cancels, Stop with flatten, like a rule's liquidation) take ids from the core's counter, which can repeat an id a `TradingHandle` already gave out; the in-app host (phase c) must fix that before strategies run in the app.
- Symbol picker: searches the built-in catalog only (no provider symbol lookup yet); front months use the calendar rule (no live volume before connecting). The CQG mock serves ES only. Recents/favourites live in `<config dir>/settings.json` (versioned; see Saved files).
- Verified on Windows 11, and by hand on macOS 27 (Apple silicon, Retina 2×; screenshots byte-identical across runs there too). Linux: CI only.
