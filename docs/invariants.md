## Invariants (enforced by tests)

- Prices are vendor-neutral: `Price(i64)` is an integer count of the *catalog product's* price unit, whose size is an exact rational `PriceScale` defined once in `catalog.rs` (ES/NQ/MES/MNQ: 1/100, tick 25 units). Quantities are `Qty(i64)`, a count of `10^-decimals` of the base unit (futures: decimals 0). No core type is in any vendor's units.
- Each provider converts its wire values exactly at its edge. CQG converts `scaled_price` with `UnitConverter`, from `correct_price_scale` turned into an exact rational. Coinbase parses decimal text, and REST numbers via `RawValue`. Sierra converts `f32 / multiplier` with an f32-relative tolerance, and the result must be on the tick grid. Values that aren't exactly representable are counted (`MarketEvent::Rejected`, import report), never rounded. CQG metadata whose tick disagrees with the catalog is a fatal `BadMetadata`.
- Vendor symbols exist only inside `lines-feed` (the crate-private `catalog::roots` table and `src/{cqg,coinbase,kraken}`) and the dev-only `lines-sierra`. The UI sees `Product`, `ContractKey`, `Capabilities` and the provider id. Bid/ask display is capability-gated.
- `ProviderSession`s do no I/O. HTTP responses arrive as `FrameKind::Http` frames carrying `URL
body` (pre-URL recordings: body only), so recordings contain them and sessions interpret a response by its URL, not their own request plan. Replay drives the same session code; its clock is the recorded frame time (the first recorded frame before any delivery).
- `.lfr` is format **v3**: header = provider, protocol, catalog product symbol, contract key. v2 files still read, with the contract unknown (shown as "contract unknown"; asking a v2 file for a specific contract is an error). v1 is rejected. Replay refuses unknown providers or protocols and product/contract mismatches. A recording holds exactly one contract: if the front month rolls mid-recording, recording stops. Imported data uses provider `lines` / protocol `lines-events-1`. Each frame is one atomic batch, depth included, so the store applies it under one lock and checks for a crossed book only at frame boundaries.
- Sierra import is deterministic (same inputs → byte-identical file). Trades are checked against the book at emit time, never against look-ahead state. Sweep fills (Sierra unbundled trades) are not expected at the touch.
- Products vs contracts (decision 0013): the store is keyed by contract (`ChartData::contract`). `MarketEvent::ContractChanged(key)` retires the old contract's bars (kept, unadjusted, for continuous charts), never mixes them. Front month = `roll::resolve_front`: volume crossover when prior-session volumes are given, else the product's calendar rule, never backwards, never an expired contract. Live feeds following a product re-resolve on every (re)connect. Nothing rolls positions.
- Trading sessions (decision 0017, `lines_core::sessions`): a session belongs to its trade date; the ETH session of trade date D opens at `eth_open` on the calendar day before D (CME's Sunday 17:00 CT open is Monday's session) and closes on D. Hours are exchange-local in an IANA zone (jiff, bundled tzdb, so results never depend on the machine). Holidays/early closes are versioned data (`lines-feed/data/exchange-holidays.txt`, format 1, every date `verified` or `unverified` with sources); a `halt` holiday is not a trade date and its morning belongs to the next trade date's session (`Session::halt`), at most one per gap. Outside a table's coverage weekdays are assumed regular and sessions report `HolidayData::NotCovered`. Session queries never allocate (`lines-core/tests/sessions_no_alloc.rs`).
- Continuous series are display-only (`continuous::build`): unadjusted by default, difference back-adjust as an option (exact, on the tick grid), no ratio adjustment.
- Sierra contract from the file name: 2-digit years are 20YY; a 1-digit year is the earliest matching year not before the file's last record.
- History + live stitch (`lines_core::stitch`, roadmap 4): a history snapshot is bars plus a *closed* `as_of` (includes every trade with `time <= as_of`, none after; CQG's `up_to_utc_time` definition). Live trades with `time <= as_of` are dropped as already counted; later ones are added; trades applied before a late snapshot overwrote their bar are re-applied from a bounded journal (500k trades while history is outstanding, then the newest 3 bars). Open/close follow trade time, not arrival order. Providers must supply a closed `as_of`: CQG `up_to_utc_time` (the mock never stamps a trade at or before its last snapshot); Coinbase candles closed at the bucket end, the forming bar rebuilt from REST trades de-duplicated against websocket trades by `trade_id`. REST lags the websocket by seconds, so id holes (REST newest .. `last_match`, and matches dropped mid-stream) are fetched by id (`trades?after=hi+1`), retried on the keepalive tick, and reported as a history gap after 6 attempts; history is `Complete` only once the REST-to-websocket hole is closed. Every (re)connect requests history from the newest stored bar; the window is `FeedConfig::history_ms` (default 3 days). `ChartData::history` (`Loading`/`Complete`/`Incomplete`/`Unsupported`) is shown as header text.
- All CQG `sint64` times are ms offsets from `LogonResult.base_time`.
- Depth (roadmap 5): `MarketEvent::BookClear`/`BookLevel` (new total per price, 0 removes); one frame is one atomic batch. CQG subscribes at `LEVEL_TRADES_BBA_DOM` and maps `TYPE_BID`/`TYPE_ASK` quotes; a snapshot clears the book. The CQG mock keeps a 10-level, one-tick-wide book that shifts with its price walk and is never crossed at a frame boundary. Coinbase uses the public `level2_batch` channel (`level2` needs authentication). Kraken spot subscribes `book` at depth 100; the session keeps its own book truncated to that depth (Kraken expects clients to drop levels pushed past it) and checks Kraken's CRC-32 of the top 10 levels after *every* message (each field is the value in grid units, so the checksum string is integer digits, never a float). A mismatch is counted, clears the book at once (`BookClear`; a book known to be wrong is never shown), and resubscribes; updates are ignored until the fresh snapshot. Kraken Futures books have no checksum: their sequence number must advance by one, and a skip is the same clear-and-resync (counted as a resync, not a `Gap`: `Gap` means dropped trades to the store and the local data store). `FeedStats::{book_checksums_ok, book_checksum_mismatches, book_resyncs}` count all of it. Kraken sessions validate tick and lot size against Kraken's public metadata (`AssetPairs`, Futures `instruments`) before subscribing: a mismatch is a fatal `BadMetadata`. Kraken Futures candle *volumes* are float sums printed to 16 digits (`0.3359999999999999`); only they are snapped, and only within 1e-6 of a grid step (`kraken::num::units_from_float_text`); everything else Kraken sends is parsed exactly from its text. Trades carry `aggressor: Option<Aggressor>`: CQG `sales_condition` (HIT/SELL_SIDE → sell, TAKE/BUY_SIDE → buy), Coinbase from the maker side (opposite), Sierra from the import.
- The store's `tape` (8192 prints) and `vap` (volume at price since data start for the contract) take only trades the stitch counts as new, so a re-delivered trade is never counted twice. Coinbase delivers the forming bar's REST trades as a closed snapshot (every REST trade before the newest REST timestamp `t_n`, `as_of = t_n - 1 ms`; trades at `t_n` follow as trades), so a reconnect inside the same minute replaces the bar instead of adding to it.
- DOM ladder (`lines_core::ladder`): rows are integer ticks × grouping (`row = floor(price / (grouping × tick))`); grouping only sums exact `Qty`, never rounds. `build_ladder` scans only the visible price range into a fixed-capacity buffer: per frame it visits at most `3 × rows × grouping` book/volume levels whatever the book depth (`tests/depth_stress.rs` asserts this at max replay speed, plus builds paced by the 8 ms UI tick, not the feed). Centring follows the inside market when it leaves the middle half of the rows, never while the pointer is over the ladder; C re-centres. Locked/crossed books are labelled and outlined, not only tinted.
- Panes (`lines-app/src/pane.rs`): chart, DOM and T&S are independent; each is given (`PaneFeed`, theme), owns its view state, polls only its own store's revision and is rendered as a cached view, so a tick on one market repaints only the panes showing it. Charts and T&S poll `ChartStore::chart_revision`, which depth below the touch doesn't move (a busy book repaints only the DOM). Panes never reference each other; a symbol switch emits `FeedChanged` and the workspace forwards it to the pane's link group. Feeds are shared through `FeedRegistry` keyed by (source, product, contract, follows front month); the last `Subscription` dropped stops the feed on a background thread. The layout is a value (`layout::Layout<PaneId>`; saved as `Layout<PaneDoc>`), rendered from `Layout::place` so drawing and hit-testing share one geometry.
- Workspaces (decision 0016): workspace → windows → tabs → layout → panes. Link groups (A–D, colour + letter, or unlinked) span all windows; joining a group adopts its market. Only the active tab of a visible window is rendered; every other pane is marked hidden and its poll doesn't notify, so hidden tabs and minimised windows do no paint work (`--bench` exits 2 if its hidden tab painted). Focus is always drawn (violet outline; dim when the window is inactive). Keys go through one capture-phase handler: `commands::command_for` (pure, tested) maps them to `Command`s, which the context menu also issues; pane keys (letters, C/G, Home, Ctrl+K, Ctrl+D, Alt+M) are never bound. Crosshair sync (opt-in per workspace, Ctrl+Shift+X) is keyed by link group (`tabstate::crosshair_peers`: same group, unlinked with unlinked): a chart emits `CrosshairTime` (time, price, product) after paint; its peers mark that bar (`geometry::time_slot`, missing in a gap). Optional price sync (`crosshair_sync_price`, palette/tab menu) also marks the price, only between charts of the same product (`tabstate::syncs_price`).
- Hide / detach (roadmap 5b): a hidden or detached pane keeps its leaf, so its tab's layout keeps every ratio and showing or re-attaching restores the exact size and position (`Layout::place_where` gives a wholly hidden side's space to its sibling). Hidden panes keep their feed, link and settings and paint nothing (`--bench-hide-doms`). A detached pane stays owned by its tab (same link group, subscriptions) and is rendered by a `PaneWindow`; closing that window re-attaches it, never loses it. "Chart only" hides a chart's linked DOM/T&S in its tab as `chart_only` and restores exactly those; panes the trader hid stay hidden; detached ones are untouched. A tab always keeps one shown pane. A window shows its tab bar only with two tabs or more (`tabstate::shows_tab_bar`); the workspace status (name, crosshair sync, report, hidden/popped-out panes) is always in the footer, and Ctrl+T, the pane menu and the palette make a second tab. Closed tabs go on an in-memory stack (10) as their saved form (feeds stop) and Reopen brings them back at their index; closing the last tab of the last window replaces it with a fresh tab. Footer notices (`notice.rs`): the same message replaces itself with a count (`×3`); refusals expire after 6 s (one timer each, nothing ticking); problems that need action (files unreadable/unsaved) stay until clicked. Hover controls (pane header, tab ×) are built only for the pane/tab under the pointer, found from geometry on mouse move: the window root re-renders every frame, so per-pane chrome costs every frame (this was measured: ~25% on the 6+2 benchmark).
- Table columns (DOM, T&S, journal; the journal leaves out, for the frame, columns a narrow pane can't hold whole): each pane paints a header row; its dividers resize (drag; double-click fits the column to its widest current content) and right-click opens a window-wide column menu (show/hide, fit, reset; the price column always stays; the DOM's orders column is hidden until trading exists). Layout is `lines_core::columns` (pure, fixed arrays, covered by `no_alloc.rs`): a column is never narrower than its title or widest current number (measured each frame from cached glyphs), and one column takes the leftover width (DOM volume, T&S time; else the last shown). Drags are absolute (start width + pointer offset) and the divider follows the pointer: the column resized is the one on the divider's anchored side (left of the fill column: the left one; right of it, as in T&S: the right one), and it grows only as far as the fill column can give way (tested for every divider, both ways, both tables). Every action is `Command::Columns` (palette too). Saved per pane as optional `columns` maps holding only what differs from the defaults (no version bump).
- Unservable panes (`feeds::Fallback`, decided once at startup): when the source serves exactly one contract (a replay) and no `--instrument` was given, a pane whose symbol it can't serve adopts that contract for the run (`feeds::resolve`, pure); its saved target is untouched, so autosave keeps the workspace's symbol, and its header says "replay: NQU25 (workspace: ES)". Otherwise an unavailable pane offers a one-click switch to the source's symbol (replay contract, else default product): a button plus Enter, `Command::ShowSourceHere`; saved like a picker switch. When every pane of a tab (two or more) is unavailable, the tab shows one "Switch all panes" banner instead (`tabstate::switch_offer`, `Command::ShowSourceInTab`).
- Diagnostics (roadmap U1): `logs` writes `tracing` to stderr and, for the interactive app only (never headless, screenshot or benchmark runs), to rotating files `<data dir>/logs/lines.log`, `lines.1.log`… (default 5 × 10 MB; `LINES_LOG_DIR`, `LINES_LOG_FILES` 1–50, `LINES_LOG_MB` 1–1000) on its own thread (lines dropped and counted, never blocking). Every line is redacted (`redact::text`) before it reaches the disk; a panic hook writes the panic and a backtrace synchronously. `LINES_BUILD_REV` (build.rs: env, else `git rev-parse` + `-dirty`) is logged at start. "Export diagnostics…" (palette, pane and tab menus) writes one zip (`zipw`, deflate on flate2 + crc32fast) to a folder the user picks (default Downloads) off the UI thread and shows its path: README, `about.json` (version, build rev, OS, GPU adapter, scale, displays), `logs/`, `config/` (settings and workspaces, redacted by key with `redact::json`), `feeds.json` (per feed over the last 5 minutes, sampled every 5 s: updates/frames per second, gaps, rejects, reconnects, checksum mismatches, resyncs), `frames.json` (per pane paints/s, chart paint µs). Nothing is uploaded; level data is never included. `diagnostics::tests::no_secret_survives_into_a_bundle` plants fake credentials, account ids, keys and e-mails in settings, workspaces and logs and checks none survive. Never log credentials, account ids, API keys or level values from paid sources; redaction is the second line of defence, not a licence.
- Saved files (`settings.json`, `workspace.json`, `workspaces/<name>.json` under `persist::config_dir`, `LINES_CONFIG_DIR` overrides) carry `"version"`. Reads go through `versioned::load`: older versions migrate forward (the old file is kept as `<stem>.v<N>.json`), newer or unreadable files are copied aside (`<stem>.v<N>-<ms>.json`, `<stem>.unreadable-<ms>.json`) and reported inline, then defaults load; a file that can't be backed up is never saved over. Saves are atomic with `<file>.bak`, on the `persist::Writer` thread (never the UI thread). Workspace format is v3 (v2: pane `state`, detached `window`; v3: the `journal` pane kind, so an older build reports a file with a Journal pane as newer instead of failing on the kind); v1 and v2 migrate (tested, pinned) and v3 is pinned; changing it needs a version bump and a migration. Screenshots and the benchmark read and write no user files.
- Chart layers (`chart_view::ChartLayer`): `prepare` under the store lock after the viewport update, `paint` inside the plot after the candles; neither may allocate. Paint order in the plot: grid, volume profile rows (behind the candles), candles (minus the bars the footprint draws as cells), footprint cells, `layers`, indicator studies (VWAP lines), the profile's label, last-price line, crosshair. The footprint (`footprint::FootprintLayer`) is held typed like the profile, because the candle loop asks it which bars it covers (`covers`, indexed from the visible range's first bar, the same range the candle scene uses). The volume profile (`lines-app/src/profile.rs`) implements `ChartLayer` but is held typed by `ChartView` (its rows paint before the candles, its label after the studies); it is not an indicator-engine node: the engine's series are per-bar sums and lines, not per-price volume, and visible-range mode depends on the viewport.
- Indicators (decision 0017): every feed's batches reach the indicator thread through `indicators::EngineTap` (beside the store writer); the engine runs `lines_indicators::Graph` in feed order (deterministic). A feed's base series (`Spec::Market`) lives as long as its `ChartStore` (a finished replay can still get indicators). Identical (feed, spec) requests share one node. Consumers get an `IndicatorHandle` whose `OutputCell` the engine updates in place (only changed points) with an atomic revision; panes poll it via `Pane::changed` and `try_lock` in paint. VWAP: accumulators are exact `i128` (`3pv`, `9p²v`, `v`, so bar typical prices `(H+L+C)/3` stay integer); a bucket is exact only if its trades all arrived as trades (after the newest snapshot's `as_of`, or from a replay's first recorded frame (`Input::TradesFrom`), no gap/disconnect), else bar-derived and the point is flagged approximate until the next reset; the value is `f64`, never an order price. Resets come from the sessions calendar (ETH default, RTH, week, month of trade dates) or an anchor bar. Drawn by `studies.rs` beside the `ChartLayer`s (same prepare/paint points; the trait is unchanged) as a smooth anti-aliased path through bar centres plus band polygons; GPUI tessellates those paths per frame (its allocation), the column geometry is allocation-free. A chart's indicators are saved in its `ChartState.indicators` (optional, empty by default). Screenshot mode waits for the engine (`engine().sync()`) before drawing.
- Footprint (roadmap 10e, `lines_core::footprint`, app `footprint.rs`): a chart bar's cells are the merge of the store's 1-minute footprints over its bucket `[bar.time, BarsView::end(i))`, never a separate per-timeframe store, so every timeframe sums the same trades (tested against footprints counted directly at 5m/15m/1h). Counted trades only. POC uses `ProfileRows::build` (the profile's tie rule); imbalances compare diagonally (`buy[r]` vs `sell[r−1]`, `sell[r]` vs `buy[r+1]`; an empty opposite counts as 0, the own side must reach the minimum, in whole quantity units) and are marked by shape and position (an underline under the imbalanced side's number, never at the column's left edge where the vertical open/close strip is), not color alone. Volume without an aggressor side is never dropped silently: a cell of only such volume prints `?N` (never `0 | 0`) and the legend counts it. `FootprintFrame::build` checks the trades' own row extent against its buffer before `ProfileRows::build`, so it never grows it. **A drawn cell always carries its numbers, whole**: `prepare` keeps a bar as cells only if its whole column is on the plot, every number fits its room (`numbers_fit`, from the font's measured tabular digit widths; quantities print through `QtyFormat`, so crypto decimals count), rows are at least `MIN_TEXT_ROW_PX` tall, and no cell lies under the readout/legend block (`set_legend_block`, from the last render); otherwise the bar is its candle and `Fallbacks` says why in the legend (the chart re-renders when they change). Never a shaded cell without its number (it would read as nothing traded). Auto-fit raises the range's top clear of that block (`clear_top`). Horizontal price/crosshair lines break across drawn cells (`hline_segments`). Tested with Kraken 8-decimal quantities and ES 1h/1D volumes (`check_drawable`).
- Cumulative delta (roadmap 10e, decision 0017): `Input::Trade` carries the aggressor; `MarketSeries` keeps per-bucket `DeltaSums` (exact buy/sell sums and the running delta's extremes in arrival order; no side = neither). A bucket that isn't exact uses its bar's tick-rule estimate (`DeltaSums::bar`) and flags every point to the next reset approximate, like VWAP. `CumDelta::update` follows VWAP's incremental contract (returns the point *before* the recomputed ones: its `forming` flag may change). On a higher timeframe a chart bar's candle merges its bucket's 1-minute candles; a reset inside a bucket shows only the last period (`render::build_delta_candles`). One per chart (adding another replaces it): there is one sub-pane.
- Chart sub-pane (`lines-app/src/subpane.rs`, pure): the plot and the sub-pane share the viewport's x (bars line up) and the time axis sits below both; the vertical crosshair runs through both, and in the sub-pane only time follows the pointer (no price tag, no price sent to crosshair sync). Shown only while a visible sub-pane study exists and both panes fit their minimums (60/30 px). The ratio is clamped on load (`clamp_ratio`: a damaged value falls back to the default) and saved only when moved (`ChartState.subpane`, optional).
- Volume profile (`lines_core::profile`): the store adds each counted trade (the same ones as `vap`) to its ETH session, its RTH session (if inside RTH) and its bar's footprint, split by aggressor; nothing is rebuilt from trades, a late trade goes to its own session, and the newest 30 sessions per kind are kept. Rows use the DOM's grid (`row = floor(price / (grouping × tick))`). POC = largest row, ties nearest the middle of the profile's range, then the lower; value area grows from the POC one row at a time, larger neighbour first, both on a tie, until `100 × va >= pct × total` (integer). Building rows is allocation-free within the buffer (`tests/no_alloc.rs`; wider profiles get a coarser grouping). The layer grows from the plot's left edge (never over the live edge or the price axis); a profile whose range began before the first counted trade is labelled `partial from HH:MMZ`.
- Studies menu (`study_menu` model, pure; `study_menu_view` render): the `Studies` command (Ctrl+I, the chart's "Studies…", the palette) opens one menu for VWAPs, the volume profile (Alt+V stays) and level sources: "On this chart" rows (hide / edit / remove), an inline editor of clickable, keyboard-navigable controls, a type-to-filter Add catalog (as the picker), and templates. Every change is a `StudyAction` on the chart's `StudySet` (indicators + profile + levels), applied by `StudySet::apply`. Anchored VWAP waits for a click on a bar (`anchor_at`; Esc cancels). Hidden studies keep their configuration and do no work (a hidden VWAP holds no engine node). Scope (decision 0021): changes apply to the chart; "Save as default for new charts" and named templates go to `settings.json` (`chart_defaults`, `study_templates`: optional fields); new panes (not restored ones) start with the defaults. VWAP display options (width, label, hidden) are `lines_indicators::Display`, flattened and optional. The menu occludes only itself: the chart keeps painting.
- Study visibility (`wsdoc::StudyVisibility`, per chart pane): `hide_study_labels` (no legends or study tags; studies drawn) and `hide_studies` (no study is prepared or painted, configurations and engine nodes kept, so showing again is exact). Commands (decision 0018) in the palette, the chart's pane menu and `commands::BINDINGS`: Ctrl+Shift+L study labels, Ctrl+Shift+I studies, Ctrl+Shift+M Clean chart (study labels and key hints off; again restores both; hidden studies stay hidden), F1 key hints (workspace `hide_hints`, shown by default). Hiding the hints removes their text; the footer itself goes only while the workspace status has nothing beyond its name (hidden/popped-out panes, sync, reports keep it: `StudyVisibility::footer_shown`). All are optional workspace-file fields written only when set. "Performance stats" (palette/menu, workspace `show_perf_stats`, off by default) puts feed msgs/s, updates/s, the chart's paints/s and paint time in chart headers; otherwise headers carry no debug stats (docs/design.md §1). Legends and the profile tag sit on `theme.label_bg` (AA over any chart content, tested). Header quotes without a value read `bid —`, dimmed.
- External levels (decision 0022): a `lines_feed::levels::LevelSource` (registered with `levels::register`; official builds will forward from the extension point's `Extensions`, decision 0020) opens its own `LevelTransport` (credentials stay in the adapter) and has a pure `decode(ctx, chart prices, previous map, frames)`. The levels runtime (own Tokio thread, one shared task per source + product + contract) fetches per `RefreshMode` (poll / SSE / one-shot), optionally records each batch (`<source>-<PRODUCT>.lfr`, provider `levels`, protocol `lines-levels-1/<source>`), and in replay decodes the recorded batches when the chart's market clock reaches them (`wait_settled` before screenshots). A market replay never runs a source live (`runtime::mode_for`): without `--replay-levels`, or with no file for a source, that source is missing, "not recorded for this replay", and draws nothing; only `synthetic()` sources (the demo) still run. The legend and the drawn levels read one per-frame `LevelsLayer::snapshot`, taken at render before the legend is built. Maps are validated off the UI thread (`Tick` values must be on the grid, `Raw` values are kept and only rounded when drawn); a refused batch keeps the previous map, shown stale. Freshness: missing (nothing yet), current, stale (older than the source's `stale_after`, or the last refresh failed), on the wall clock live and the replay clock in a replay. The chart layer (`levels_layer`) draws zone fills behind the candles, lines and edges above them, labels last (source colours for lines/zones: the 0022 exception; labels in theme text on `label_bg`, moved off the last-price row); stale maps are dimmed, missing ones draw nothing; the legend says which. `LevelsConfig` per pane (optional `levels` field: all, labels, per source, per `source/kind`), under the chart's study visibility (hide studies hides levels; hide study labels and Clean chart hide their labels and legend rows). `lines_core::levels::price_at`: the open of the bar starting nearest T within a tolerance, else `None` (adapters withhold translations then).
- Axes (inspiration.md, charts; behaviour reimplemented, no code reused): gridline steps come from fixed tables, the smallest step whose labels clear a minimum spacing measured from the label font (`GridSpace`). Price steps (`geometry::price_step`) are tick multiples, nice in the price's notation: decimal {1, 2, 2.5, 5}·10^k, 32nds halve a point then whole points, odd ticks fall back to {1, 2, 5}·10^k ticks. Time steps (`time_step`) are whole bar periods from 1 s to 8 weeks (weeks start Monday, UTC). A time label carries the date only on the view's first line and the first line of each new UTC day (`TimeLabel`). Axis labels a tag would cover (last price, crosshair or synced price, the time tag) or that would run under the price axis are not drawn (`label_clear_of_tags`). A new bar shifts the view only while the newest bar is visible (`Viewport::follow_live`), so a view scrolled into history stays put. Double-click resets only what was clicked: the plot both axes, the price axis auto-scale, the time axis bar width and live edge (`Viewport::reset_time`). Magnet crosshair (per chart, saved as optional `magnet`, Ctrl+Shift+G): over a bar the price snaps to the nearest of its OHLC (`geometry::magnet_price`).
- DOM price trail (`lines_core::trail`, `lines-app/src/dom_trail.rs`): per DOM row (the ladder's grid) two accumulators, aggressor buy and sell volume (no aggressor: tick rule; the first such trade half each), decaying exponentially on the feed clock (`ChartStore::feed_clock`: newest frame or market time, plus the silence only while live; frozen otherwise, so replays and screenshots are deterministic and a finished replay is a still picture). Half-life 0.5–5 s (default 1.5 s). A fixed ring of 512 rows around the newest trade, recentered without allocation. It takes only the prints the store counted (its tape ring, by sequence number), so nothing counts twice. Opacity = `sqrt(volume / scale)` capped at 0.6, where the scale follows the 90th percentile of active rows (up in ~1 s, down over ~30 s, still while nothing trades), never the instantaneous max. Net bought rows use `up`, net sold `down`, mixed rows lean to neutral; a chevron on the newest trade's row shows which way the last price moved. Own DOM column `trail` beside Price (fill only), shown exactly while the trail is on. Frames: a shown DOM asks only when it has not painted for 33 ms (data paints count), only while a cell is above 0.03 opacity and the feed clock moves; it stops after about ten half-lives (tested), and `--bench-expect-idle` passes with `--dom-trail`. Off by default; per-DOM optional `trail` field (enabled, half-life); commands `DomTrail` and `DomTrailHalfLife` (palette, DOM pane menu; no keys). Allocation-free (`no_alloc.rs`).
- Drawings (roadmap 11, `lines_core::drawings`, `lines-app/src/chart_draw.rs`, `drawings_store.rs`): anchors are data space, a time and an exact `Price` on the tick grid, never pixels or bar indices. A time maps to x through the chart's own `TimeAxis` (a bucket's start is its bar's slot, the elapsed fraction of the bucket goes between slots), so a 1-minute anchor sits proportionally inside a 15-minute bar and returns exactly to its minute; viewing never changes an anchor. Editing snaps time to the start of the bar under the pointer on the chart edited on, and price to the grid (or the bar's O/H/L/C with the magnet); a file's off-grid price is skipped and reported, never rounded. Projection, hit-testing, snapping and the measure's text don't allocate (`no_alloc.rs`). Drawings belong to the product, never the pane or the workspace file: `<config dir>/drawings/<PRODUCT>.json`, format `drawings` v1 (v0 migrates; v1 pinned in `drawings_store::tests`), one shared `ProductDrawings` per product whose revision every chart of it polls; saves go through `persist::Writer`; screenshots and the bench keep them in memory (`--drawings FILE` seeds them). Every change is one undo step (a whole drag, delete-all). Input stays separable from chart trading: drawings take a press only in drawing mode or on the *selected* drawing (a handle, or its body to move it), never with Ctrl/Cmd; a press on an unselected drawing selects it and the chart still pans; zones and measures are hit on their edges only, so the chart pans inside them. Drawing keys are `Command::Draw` bindings (Alt+H/T/Z/L/N/U, Alt+Shift+H/T, Ctrl+Z/Y); Alt+M (picker) and Alt+V/R/B/G (profile) stay unbound. While the focused pane takes typed text (`takes_text`: picker, note, timeframe entry, studies menu) the workspace leaves plain and Alt keys to it (`commands::runs_while_typing`). Drawing colors are theme tokens `drawing[4]`: 3:1 on the chart and CIEDE2000 ≥ 20 from every color with a meaning (up/down of both palettes, accent/last, warn, `order_target`, `order_stop`). Dash patterns are theme constants: drawings `DRAWING_DASH` (12/4) never match the position line (`POSITION_DASH`) or held orders (`HELD_DASH`); horizontal and vertical drawing lines sit on device pixels (`chart_draw::crisp_band`). The measure's readout shows exactly what `pnl_display` allows (off: neither ticks nor money; points, bars and duration always), re-shaped when the setting changes, on an opaque panel above every drawing stroke, and never extends past the measured range's newer end. Per-chart `ChartState.hide_drawings` is optional; hiding studies and Clean chart leave drawings shown.
- Chart timeframes (roadmap 9, `lines_core::timeframe`): the store keeps 1-minute bars only; a chart on another `Timeframe` (1 2 3 5 10 15 30 m, 1 2 4 h, D, W) draws `Derived` bars: exact aggregation (open of the first, max/min, close of the last, summed `Qty`). Minute/hour buckets align to the product's ETH session open (DST through the calendar), never span a session break (daily close or holiday halt: each side aligns from its own start; a cut bucket is *partial*, shown in the crosshair readout); Day = one session (its trade date), Week = the trade dates Monday–Friday; no calendar (or outside sessions): UTC. `Derived::update` reads `BarSeries::changed_since` (a 32-entry change log): a tick on the newest bar is O(1), a new bar or a history fill re-aggregates from the earliest bucket it touched, a trim or a lost log rebuilds; buffers are reserved for the series' capacity, so updates never allocate (`no_alloc.rs`). Layers get the chart's `BarsView` (bars + bucket ends): VWAP samples the engine's 1-minute line at each bucket's last point, approximate if any point in it is (`render::build_columns`); the visible-range profile merges the bars' 1-minute footprints; crosshair sync maps a time into each chart's own bars (`BarsView::slot`). D/W axes and crosshair tags show trade dates. Timeframes are per chart (link groups share only the market), saved as an optional `ChartState.timeframe` (`"5m"`; absent or unknown = 1m, no version bump). Switching keeps the pointer's time in place. Typing on a chart: digits then an optional unit (`5`, `15`, `1h`, `1d`, `1w`) + Enter; bare letters still open the symbol picker, so `d`/`w`/`h` alone are not timeframes there. `Command::Timeframe(tf)` (palette "Timeframe: 1m" … "1W") and `Command::TimeframeMenu` (header chip, pane menu); no key bindings. The header chip (`pane::timeframe_chip_text`) sits between the contract and the account chip, inside the header content clipped before the hover controls' gutter; a pure model of the left group in `pane`'s tests keeps it before the gutter at `CHART_HEADER_MIN_W` for every product, timeframe and default account. Seconds/tick/volume/range bars are phase 2 (roadmap 9b): `Timeframe::source()` = `BarSource::Trades`, built from counted trades.
- Crosshair hit-testing and snapping are pure (`lines_core::geometry::crosshair`). Input handlers store only the pointer position; paint hit-tests after the frame's viewport update. Lines use device-pixel snapping: wicks, time gridlines and the crosshair's vertical line sit on device-pixel centres, and candle bodies are an odd number of device pixels wide.
- No heap allocation in our paint path (`lines-core/tests/no_alloc.rs`, counting allocator: chart, and DOM/T&S rows and formatting). Chart label text is shaped once per value and cached; a cache miss allocates. DOM and T&S numbers are painted from per-character glyphs shaped once (`text::Glyphs`), so new values don't allocate. GPUI allocates internally per frame.
- Local store (`lines-feed/src/disk`, decision 0019): per contract `store-v1/<source>/<contract>/<trade date>.lseg`, append-only **segment v1** (header like `.lfr` v3 + source, encoding, trade date; blocks `u32 len | u32 crc32 | i64 time_us | lines-events-1`, one block per feed frame). Opening a segment for writing truncates at the first invalid block (torn tail; never repaired); readers stop at an incomplete block without consuming it, so they run alongside the writer. One `ContractWriter` per contract, owned by the feed (`EventSink` in `connection.rs`), exclusive via `writer.lock`; file I/O on its own thread. Flush policy: write when 256 KiB are buffered or every 200 ms, `sync_data` at most every 1 s and on close (crash loses ≤ 200 ms, power loss ≤ ~1.2 s). Stored: trades (with aggressor) and best bid/ask; depth only for `--store-depth` products. Not stored: provider history (it lives in the bar index), so a stored session replays its *trades*.
- Bar index (`bars`, CRC'd, replaced atomically) is a cache of the chart's bars, saved every 30 s and at each disconnect; rebuilt from segments if missing or damaged. Startup: the feed thread loads it into the chart store before connecting (panes show it at once), then requests history from the earliest hole in the bar coverage inside the window (else the newest bar); `lines_core::stitch` merges without double counting.
- Coverage (`coverage`, text): `bars` and `trades` ranges known complete. Claimed only after `HistoryComplete`: bars from the requested history start, trades from the newest snapshot `as_of` + 1 ms, both to the newest of feed time and trade time. A `Gap` closes the claim; a `HistoryGap` is excluded; a disconnect ends it. Trade claims count only where the segment file still exists (eviction) and stop at the last valid block after a torn-tail cut. Coinbase reports history beyond its page budget as a `HistoryGap`.
- Partition = session trade date via `disk::partition::trade_date` (from `catalog::sessions`; data outside every session goes to the next session's date; products without a calendar use the UTC date).
- Retention: oldest trade dates first across all contracts until segments fit the budget (default 4 GiB); segments being written are never deleted.
- Stale (docs/design.md §7): `ChartStore::stale_for()` (lock-free) is `Some` while the feed is `Live`, its market open, and nothing arrived for longer than `stale_after` (5 s; CQG 10 s; `FeedConfig::stale_after` overrides). Panes poll it with their revision, show a `STALE · no data N s` badge, and the DOM and T&S dim. Market-open comes from the product's sessions calendar, evaluated at the feed's clock (last market time + silence), so a closed market is never stale and replays stay deterministic.
- Latency HUD (roadmap 6b; `lines_core::latency`, app `latency_hud.rs`): off by default (`Workspace::show_latency_hud`, optional saved field), mirrored in the process-wide `latency::enabled()`; while it is off nothing records (one relaxed load per feed frame and per paint), a chart drops its receive → paint window and a feed's `ChartData::latency` is freed on its next frame; the trading core's two order windows (~62 KB) exist from its start and keep their samples across a toggle (`tests/latency_hud.rs` in lines-feed and lines-trading). Windows are 60 one-second histograms of quarter-octave buckets, keyed by the caller's clock in ms: feed exchange → receive on the frame's receive time (a replay's recorded time, so replays and screenshots are deterministic), order click → sent and the ack round trip (first ack of a `Submitted` order, `at − created`) on the trading core's clock, receive → paint on the monotonic clock from the last update that moved `chart_revision` (depth below the touch doesn't reset it), recorded only for frames that draw the data; while the pane is hidden its poll marks updates seen (`Pane::on_hidden_tick`), so a hidden tab's wait is not paint latency. The order windows read at the newer of the core's clock and the chart's feed clock, so they age out while the core idles. Back-fill is not latency: HTTP frames and frames a session flags with `ProviderSession::backfill_frame` (Kraken's trade snapshots) are left out, and so is any trade more than 60 s late; a session that streams past trades must flag them. Every lock is copied from and dropped before text is built; the trading core and the UI only `try_lock` the order windows (decision 0012). A quantile is its bucket's upper edge (never below the true value, at most 25% above). Feed and ack are whole milliseconds (`<1` below that); a feed whose samples are all exactly 0 with a clock-offset bound of exactly 0 has no separate exchange time and reads `n/a` (a clock behind the exchange also records 0s, but a negative bound). The clock line is `ClockOffset`'s bound `min(receive − exchange)` for wall-clock (live) feeds only, with a ⚠ badge (text, not color alone) beyond ±250 ms. Recording and reading never allocate (`no_alloc.rs`); the header text is rebuilt at render at most once a second, and the screenshot path switches recording on before it replays. A frozen frame leaves out the wall-clock measures (paint, order).
- Trading core (`lines-trading`, roadmap 6; decisions 0004/0005/0006/0012/0018): every order action is a `Command` in an `Envelope` (id, `Source`, the input event's `Instant`) through `TradingHandle::submit`; each gets exactly one `Event::Command` result (`Ok(order ids)` or a `Reject` with a `RejectCode` and message). Everything else comes out as `Event`s on `TradingHandle::subscribe` (Order, Fill, Position, Account, Breach, Guardrail, Strategy, Rebuilt), in order. `TradingCore` is pure (time passed in, no I/O) and runs on the `TradingService` thread; it never waits on a lock the UI holds: the only lock it shares is the latency HUD's `OrderLatency`, which both sides only `try_lock` (a sample that meets the UI reading is dropped). Order states move only along `OrderState::can_become` (Submitted → Acked → Working → PartiallyFilled → Filled / Cancelled / Rejected with a reason); nothing is Working before its ack. Money is exact: `Money(i128)` in 1e-10 currency units, `ContractSpec::money_per_unit` must divide exactly; positions are FIFO lots, so realised P&L is exact. Risk (`RiskLimits`: max order qty, max position counting open orders, price band in ticks from the last trade else the mid, daily loss) and prop rules run before the broker; `CancelOrder`, `CancelAll` and `Flatten` never pass through them. Prop rules are data (`RulePreset`, labelled "user-editable approximation", no firm names): trailing drawdown intraday (equity high-water) or end-of-day (closing balances), optional lock at start + X, daily loss per trade date, micro-equivalent contract cap (`Product::micro_equivalent`), profit target, consistency; a breach blocks new orders and, with `liquidate_on_breach`, flattens (`Source::Rule`). Day boundaries are session trade dates (`disk::partition::trade_date`) of the account's `day_product`. Reconnect/restart: `rebuild` replaces balances, positions and open orders from `Broker::snapshot`; orders the broker doesn't know become Cancelled. Every request reaches the broker through `Broker::request_in_context` with a `RequestContext`: `source`, `origin` (`Origin::of`: `Rule`/`Api`/`Strategy` automated, the rest manual) and the issuing `PaneContext` (pane contract, `ContractSelection` follows-product or pinned, the resolver's `front_month`), set by `submit_from_pane` (`TradingHandle`/`TradingCore`); plain `submit` sends `pane: None`. The default implementation calls `request`, so brokers that don't need it (paper) ignore it. Latency: click → `Broker::request` is logged as `tracing` target `lines::latency` (`click_to_sent_us`) and kept in a 4096-sample ring (`TradingHandle::latency`).
- Strategies (decision 0025, proposed; `lines-trading/src/strategy.rs`, `core/strategy_gate.rs`, `lines-strategy`): a strategy only acts through commands with `Source::Strategy(id)` (`Origin::Automated`), and the **core** enforces the rules. Each strategy command passes the strategy gate first, then prop rules, risk and guardrails as usual. The gate checks four things:
  - **State** (Disarmed / Armed / Paused / Stopped): only Armed may enter (a bracket, an order beyond what closes the position, a modify adding quantity). Every state may reduce: cancel its own orders, flatten its own contract, move its exits (a modify of an entry order, price included, is an entry), and place orders no larger than the position less what open orders and held bracket exits (each bracket once) already close. A strategy's Cancel All cancels only its own orders; its Flatten does too when there is nothing to close, but closing a position cancels every order on that contract (a trader's stop left after the position is gone would open a new one). Repricing or resizing an entry is an entry; whether a single order is closing counts the other open orders and held exits on its side. **Exits skip every check below** (hours, max position, daily loss, rate).
  - **Scope**: the instance's own account, contract and orders, with at most one instance per account and contract.
  - **Limits** (`StrategyLimits`, all required): max position (worst case with open orders), max daily loss on its own fills (its own orders, plus anyone's Flatten fills up to what closes its own position), entries per 60 s (counted only when the core accepts them), and entry hours in a named time zone.
  - **Paper only**: `Broker::simulated()` is true only for the paper broker; live brokers and a venue's own Sim accounts keep `false`.
  - Who issues controls: only a person (`Origin::Manual`) arms. A strategy may pause or stop only itself, and may never add, remove or arm.
  - `StopStrategies` is never gated and acts at once. Every instance stops before any flatten.
  - **The core pauses** an Armed instance for any of these: a manual order action on its account and contract (any contract for account-wide Cancel All or Flatten; before the action runs, even if it is then refused; the order the person modifies or cancels is left to them); the account not Active, or a guardrail lockout; the broker disconnected; its daily loss reached; no `strategy_heartbeat` for `HEARTBEAT_TIMEOUT_MS` (5 s) of core time.
  - Pausing or stopping cancels entry orders (`Role::Entry`, and singles that don't only close the position). Bracket exits and Flatten orders stay.
  - Nothing re-arms automatically. Armed state is never saved. Arming reconciles the instance's own books with the account (flat adopts flat; any other mismatch is refused: flatten first). Removing an instance disowns its remaining orders. An instance owns only the orders its own Place, Bracket and Flatten created, never orders its Cancel All or Flatten cancelled.
  - Strategies are pure (`lines_strategy::Strategy`: no I/O, no clock, `Ctx::now` passed in).
  - Backtests (`lines_strategy::backtest::run`) are single-threaded. Market frames go through the recording's own provider session (`lines_feed::recorded::RecordedEvents`, the same decode as replay); levels come from `read_recording` and `LevelSource::decode`. At one instant: levels, then market, then timer. The instance is armed once data started and every required source is current, and is never re-armed.
  - The same inputs give byte-identical `Report::to_json` (tested). Reports carry file names and FNV-1a hashes, never local paths.
- Guardrails (`lines-trading/src/guardrails.rs`, roadmap 8b, decision 0006): per account, all optional: max trades per trade date (a round trip flat → position → flat; partial fills don't count, a reversal closes one and opens the next), a losing streak (trade P&L net of every fee; below zero is a loss) → cooldown of N minutes, max daily loss in money (realised + unrealised, separate from prop rules), max position (worst case with open orders), no entries in the last N minutes before the session close. A breach is a lockout (`Cooldown` until a time, `Locked` until the trade date ends) with a reason; denials are `RejectCode::Guardrail` with a short US-English message ("Cooldown: 3 losses in a row, 12 min left"). Exits are never blocked: Flatten, Cancel All, cancels and orders no larger than what is left to close; a modify that adds quantity is checked as an entry. `Command::SetGuardrails`: tighter fields apply at once, looser ones with the next trade date; nothing clears a lockout early. Trade dates from `disk::partition::trade_date` of the account's `day_product`; a fill counts toward the trade date of its own timestamp (the broker's fill time), not the time the core processes it. `Event::Guardrail { account, state, reason, until }` on every change, its end included (the core wakes for it). Saved per account in the trading file (`SavedAccount.guardrails`, format v2). Defaults: `settings.json` `guardrails` keyed by account name (or id), asked for at every start; no editor yet (decision 0021). Screenshot scripts: `guard trades N | streak L/M | loss X | position N | close M`.
- Paper broker (`paper.rs`): deterministic, I/O-free, driven by `market` (feed batches via `lines_feed::listen` and `FeedBridge`) and `poll(now)`. Acks after `latency_ms` (default 25). Rejects off-tick prices, non-positive qty and orders while the product's session is closed. Fill models for resting limits: trade-through (default: a trade strictly through the limit), touch (a trade at the limit), queue estimate (behind the book's size at the price; trades at the price and a shrinking level reduce the queue). Several orders never fill more than a trade printed. Market orders and marketable limits walk the book; liquidity taken isn't reused until that level updates; no book → last trade; neither → reject. Stops trigger on trades at or through the trigger. Fees per quantity unit per side, by product. Brackets and OCO are held broker-side (exits Acked until the entry fills, sized to the fill; an exit fill cancels or shrinks the sibling) and saved in the broker state, so they survive restarts.
- Trade journal (`lines-trading/src/journal`, roadmap 8c): a trade is one round trip per account + contract, flat → position → flat, by `guardrails::RoundTrip` (the one definition, shared with the guardrails' counts); a reversal closes one trade and opens the next, its fill's quantity split and its fee split pro rata (remainder to the closing side). Realized P&L comes from the journal's own FIFO lots (exact; right for reconciled fills too), fees from the fills. Fills are keyed by `trade_id` within a run: a fill seen again (reconciled twice, delivered twice) never counts twice; never across runs (paper fill ids restart when the paper file is reset, and the core never re-emits an earlier run's fills). Trade ids are unique (`<first fill id>@<entry ms>`, `#n` on a collision in a file), so a new trade never replaces a saved one. MAE/MFE: the worst/best of realized-so-far + open P&L (before fees) while open, from the market batches the paper broker sees (trades and last prices) and the fills. It runs on its own thread (`JournalShared`): the trading thread's `service::Observer` only sends it messages (market batches after the core; the core's events before each market batch and after each drain, so a trade opened earlier in a batch sees the prices after it), the UI reads published snapshots (an `Arc` pointer swap) and sends edits and exports as messages: no lock is shared with the core, none is held while formatting. Only a trade closing, the open count changing or an edit publishes; market data and the core's per-batch position reports never do (tested through the service). The file is opened append-only and re-read at open, so a torn tail is cut from the file as it is then, never a stale length. The app flushes it on quit. File `<config dir>/journal/<source>.jsonl` (live sources only; replays and screenshots in memory): JSON Lines, header `{"journal":1,"source":…}`, then `{"trade":…}` / `{"edit":…}` records, externally tagged on purpose (serde's internal tagging buffers content and can't hold `i128` money); append-only on its own thread; a torn last line is dropped on read and cut before appending; a newer version is left alone and not written. Open trades aren't saved: after a restart a position the journal didn't see open is seeded from the core's position report, marked `incomplete` and dated from the first fill it sees. The Journal pane follows `pnl_display` (off: no money or tick number in rows or the stats strip; CSV export is always complete) and formats rows only when the journal's revision or the display setting moved.
- Trading file (`persist.rs`): versioned JSON (`TradingFile`, v2), migrated forward on load (v0 = no `version`; v1 → v2 only moves the version, so a build from before guardrails refuses a file that may hold a lockout instead of dropping it; v1 and v2 are pinned in `persist::tests`), a newer version is refused, writes are atomic (temp + rename); the service saves at most once a second when changed. Orders sent without a broker answer are saved (`in_flight`) and restored `Unresolved`.
- OMS checklist (docs/inspiration.md, one test each in `tests/trading.rs`, `checklist_*`): a command `Reject` is always a **denial** (the core refused, nothing sent); a broker's refusal is `OrderState::Rejected` on a sent order, and the UI labels them DENIED / REJECTED. Cancel All covers submitted and acked orders. A fill during a pending cancel applies (Filled, or Cancelled with its filled quantity); a fill reported after an order finished applies without reopening it. Every fill carries the broker's stable `trade_id` and the core drops repeats (any path); reconciliation (`rebuild`) reports fills the broker made while we weren't listening as one `reconciled` fill with id `recon-<order>-<filled>`, so repeating it never double-counts. Overfill: `OverfillPolicy::Record` (default: the broker's quantity is the truth; `Order::overfill`) or `Reject`, both reported as `Event::Overfill`, never clamped. Accounts have a `TradingState` (Active / ReducingOnly / Halted); prop breaches set it from the preset's `on_breach` (default: daily loss → reducing only until the next trade date, drawdown → halted); reducing only admits orders that close at most the open position less what open orders already close, and marks them `reduce_only`; the paper broker shrinks reduce-only orders as the position shrinks and cancels them when it is flat. Risk adds `max_notional`, `max_submits_per_sec` and `max_modifies_per_sec` (separate windows); cancels and Flatten are never rate limited. Brackets are one-updates-other: an exit's remaining is the bracket's open quantity (entry fills grow both exits, an exit fill shrinks its sibling); with nothing open the sibling is held while the entry still works and cancelled once it is done. `Unresolved` = sent with no known outcome (after a restart or a reconnect whose snapshot lacks it): never drawn as working; the DOM header lists them.
- App trading (roadmap 7; `trading.rs`, `trade_bar.rs`, `dom_trade.rs`, `dom_orders.rs`): the `Trading` global holds a `TradingHandle`; UI actions only `submit` (a channel send stamped with the input event's `Instant`) and never wait. A pump thread applies core events to `TradeState` (its own mutex, never one the core takes) and bumps a per-account atomic revision; panes poll it with their store revision (`Pane::changed`) and `try_lock` in paint. Paper fills see the pane's own feed (`follow_store`, once per feed). Paper state: `<config dir>/paper/<source>.json` per data source; replays (market clock), screenshots and the bench keep it in memory; a damaged file is moved aside and reported. Accounts: paper only; the pane header names the account with a PAPER badge (word, inverted chip). DOMs start **disarmed**; arming is explicit (header or Ctrl+Shift+Space), never saved, dropped on contract change or when trading becomes impossible, and on focus loss / window deactivation / account change (`ArmPrefs`, on by default). Armed click: bid column buys, ask column sells, limit at the row's **displayed price** (`row × grouping × tick`, the row's lowest; same for grouped rows), Shift = stop market (refused if it would trigger at once); brackets attach only to orders that open or add. Drag (orders column) = modify with a ghost until the order reports the new price; right-click = cancel; neither needs arming. Flatten / Cancel All (header, Ctrl+Shift+F / Ctrl+Shift+A, palette) act on the pane's contract, are always visible and never gated by arming, risk or rules. Header order buttons (`dom_trade::QuickOrder`) are gated by arming exactly like ladder clicks and built from the same `trade_bar::entry_ctx`; an order whose bracket has no reference price is refused, never sent unprotected; Reverse is refused while any order works on the contract (an old exit would add to the reversed position). Arming and order keys act only from a focused DOM (`trade_bar::chart_runs`: charts show no arming state). Ctrl+Alt is AltGr on Windows/Linux: a Ctrl+Alt keystroke that types a character other than its key is text, never a command (`commands::command_for`). Guardrail time left is read on the core's clock (`Trading::now`), never the feed's alone; the lockout strip dims entry buttons but the core decides, and Flatten / Cancel all never dim. Order marks: pending outline, held (bracket exit before entry fill) dashed, working solid, partial proportional fill + `filled/qty`; bracket exits by role (`dom_trade::MarkRole`): target `T` in `order_target` notched along its top edge, stop `S` in `order_stop` notched along its bottom edge, entries plain in the side's colour; refusals show as a short tag in the orders column of their row (`dom_trade::short_reason`, e.g. `closed`; `DENIED: closed` when the column is wide enough; clipped to the cell, never over the price) and as one header line with the full message and `×N`, never as dialogs. The mock source's paper broker doesn't check exchange sessions (`TradingSetup::check_sessions`, over a saved file's setting too): it is synthetic and never closes; real sources and replays keep the check. Every trading action is a `commands::TradeCmd` with a key (always Ctrl+Shift or Ctrl+Alt) and a palette entry. Latency budgets live in `#[ignore]`d perf tests only; unit tests check that samples are recorded.
